# Component Registry

**This is the single source of truth for every component in this repository.**

Before building any component, check this list. If it exists here, use it. Do not build a duplicate. When you add a new component, add it to this file in the same PR.

Every component below has a `.stories.tsx` file next to it. Run `npm run storybook` to see each one in every state.

---

## ui/: generic, reusable, no Forge domain knowledge

These components have no knowledge of sessions, mentees, attendance, or any Forge concept. They accept generic props and render UI. They must work in any context.

## forge/: Forge domain components

These are built by composing `ui/` components. They understand Forge concepts and accept typed Forge data as props (sessions, mentees, attendance records, etc.).

| Component                | File                               | Description                                                                                                                                                                                                                                          |
| ------------------------ | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `StatusChip`             | `forge/StatusChip.tsx`             | One chip for every status family: `kind` is account, invitation, session (`isLive` shows "Live"), attendance, override, activity or cohort. Labels come from `lib/labels.ts`.                                                                        |
| `TrackBadge`             | `forge/TrackBadge.tsx`             | Pill in one of the six pillar colours (`pillar`: ict, innovation, personal-dev, professional-dev, scholarship, community). Optional `label` overrides the name.                                                                                      |
| `SessionRow`             | `forge/SessionRow.tsx`             | One session in the calendar: time range, linked title, mode and track, pillar badge and status. Drafts get a dashed border.                                                                                                                          |
| `SessionForm`            | `forge/SessionForm.tsx`            | The create and edit session form (details, category, month, times, location, points, mentors, resource link). State comes from `useSessionEditor`. Session type and non-ICT pillars are disabled (API gaps). `aside` adds cards to the right column. |
| `MentorPicker`           | `forge/MentorPicker.tsx`           | Lead mentor select plus `CoMentorPicker`, with loading, empty and error hints.                                                                                                                                                                       |
| `CoMentorPicker`         | `forge/CoMentorPicker.tsx`         | Search box and toggle chips for choosing co-mentors.                                                                                                                                                                                                 |
| `InviteUserForm`         | `forge/InviteUserForm.tsx`         | Full name, email, role and cohort, sent with `useInviteUser`. `fixedRole` locks the role (used on the professional mentor roster).                                                                                                                   |
| `MenteeCard`             | `forge/MenteeCard.tsx`             | Draggable mentee with an "Assign to" select so keyboard and touch users can move them too. Used by the 1:1 groups screen.                                                                                                                            |
| `MonthBoundariesEditor`  | `forge/MonthBoundariesEditor.tsx`  | Table of KamiLimu months with start and end date inputs and a remove button per row.                                                                                                                                                                 |
| `CohortFormFields`       | `forge/CohortFormFields.tsx`       | The fields shared by New cohort and Cohort settings, driven by `useCohortForm`.                                                                                                                                                                      |
| `CohortRulesUnavailable` | `forge/CohortRulesUnavailable.tsx` | The cohort rules the API can't store yet (activity points, logging and rating windows, rating questions), shown disabled.                                                                                                                            |

## layout/: structural shell components

These define the structural skeleton of each view.

| Component                                         | File                        | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AppShell`                                        | `layout/AppShell.tsx`       | Role-aware shell for signed-in routes (used by `src/app/dashboard/layout.tsx` and `src/app/admin/layout.tsx`). Desktop: 248px sidebar with brand, cohort card, nav and user block. Mobile: top bar with a cohort pill, sticky bottom tab bar and a "Me" dialog with sign out. Desktop: 248px sidebar with the logo, the active cohort card (opens a picker when there is more than one cohort), the admin nav from `ADMIN_NAV`, the theme toggle and the user block. Below md: a top bar with a cohort pill and a menu button that opens the same items in a sheet.                                                                           |
| `NoCohortNotice`                                  | `layout/NoCohortNotice.tsx` | Shown in place of a cohort-scoped screen when there is no cohort yet, or when cohorts failed to load.                                                                                                                                                                                                                                                                                                                                                       |
| `PageHeader`                                      | `layout/PageHeader.tsx`     | Page title (22px mobile, 28px desktop), optional `subtitle` and right-side `action`.                                                                                                                                                                                                                                                                                                                                                                        |
| `TopBar`                                          | `layout/TopBar.tsx`         | Deprecated alias of `PageHeader`. ## Rules for adding to this registry

1. Add the entry to this table in the same PR as the component itself.
2. Include a one-line description that explains what the component does and any important props or variants.
3. Move candidates from "Not yet built" to the table when implemented.
4. Never remove a component from this list without also deleting the file. The two must stay in sync.
